# T-002 — Actuator + health endpoint, liveness/readiness groups, deny-by-default allowlist (#18)
Milestone: M8 (#19)   Status: pending

## Description
The app is containerized (`e5d009e`) but has no way to say whether it is alive. `docker compose`
can only report the *process* as running; `postgres` and `redis` both declare healthchecks and
`app` declares none, so it is the one component in the stack whose readiness is unobservable. Any
orchestrator — Compose `depends_on`, a Kubernetes probe, an ALB target group — has nothing to poll.

This task adds Actuator, exposes health with liveness/readiness split, and makes the endpoint
reachable through the deny-by-default filter chain via an **explicit allowlist**. The
Redis-vs-Postgres aggregate semantics are T-003; this task is "there is a reachable, correctly
scoped endpoint at all."

## The security interaction — read this before exposing anything
`SecurityConfig` was inverted to deny-by-default in #14 (see its class Javadoc and ADR-0004), so
`/actuator/**` is currently **denied** and any newly exposed endpoint stays unreachable until a
matcher is added. That is the design working as intended, and it is the whole reason the endpoint
set has to be a deliberate decision:

- `/actuator/health` — or just the readiness/liveness groups — is the only thing that plausibly
  belongs on the public list.
- `/actuator/env`, `/actuator/configprops`, `/actuator/heapdump`, `/actuator/loggers` must **not**
  be public. `env` and `configprops` would expose `security.jwt.secret` and the datasource password
  (both are read from `application.properties` at `security.jwt.secret` and
  `spring.datasource.password`).
- `management.endpoints.web.exposure.include` must be an **explicit allowlist, never `*`**.
- **Adding a blanket `/actuator/**` permitAll reintroduces exactly the default-allow shape #14
  removed, one path prefix over.** Follow the pattern already in `SecurityConfig`: the catalog
  reads are listed route by route rather than by prefix, with a comment saying why.

There are two independent levers and both should be used: **exposure** (which endpoints exist over
HTTP at all) and **authorization** (which of those are anonymous). Decide explicitly whether
anything beyond health is exposed-but-authenticated, or whether the exposure list is health-only.
State the reasoning wherever it lands.

## SETTLED BY GRILLING (2026-08-16) — see ADR-0012, do not re-decide
- **Shared port 8080. No separate `management.server.port`.** A management port gets its own filter
  chain, which would mean two authorization postures where ADR-0004's whole claim is that there is
  one, defaulting to deny.
- **`management.endpoints.web.exposure.include=health,metrics`.** No Prometheus registry.
- **`permitAll` on the health group paths only, listed route by route** in the style `SecurityConfig`
  already uses for the catalog reads. Never `/actuator/**`.
- **`/actuator/metrics` gets no matcher at all.** Deny-by-default authenticates it for free. The
  absent matcher *is* the mechanism — write a comment saying so, or someone will "fix" the omission.
- **`show-components=always` + `show-details=when-authorized`.** Anonymous callers get each
  indicator's UP/DOWN — which is what #18's "the Redis indicator shows its true state" actually
  requires — without the database engine, Redis version, or container filesystem path that
  `show-details=always` publishes.
- **`SecurityConfigIntegrationTest` owns the posture assertions.** It already holds the
  deny-by-default tests and is the natural home.

## Facts verified during grilling — confirm, don't re-research
Checked against the published Boot 4.1.0 artifacts. Re-verify rather than trusting these lines,
but do not spend the time rediscovering them:
- `management.endpoints.web.exposure.include` **already defaults to `['health']`**, so
  `/actuator/env` and `/actuator/heapdump` are not exposed today. The explicit allowlist is a
  confirmation and a guard against future widening, not a fix for a live hole.
- `management.endpoint.health.probes.enabled` **already defaults to `true`** in Boot 4 (it was
  off-unless-Kubernetes in Boot 3). Do not add a redundant line for it.
- `management.endpoint.health.show-details` defaults to `'never'`, which returns a bare
  `{"status":"UP"}` — hence the `show-components` decision above.
- `springdoc.show-actuator` defaults to `false`, so actuator paths stay out of `/v3/api-docs` and
  `OpenApiDocumentationTest`'s anonymous-401 walk will not enumerate them. **This risk is closed;
  no action needed.**
- `spring-boot-starter-actuator` exists under the Boot 4.1.0 BOM (the Boot 3 spelling is correct
  here), alongside a per-technology `spring-boot-starter-actuator-test`.

## Acceptance criteria
- `spring-boot-starter-actuator` added to `pom.xml`. **The Boot 4.1.0 BOM does contain that exact
  artifact id** (verified during planning against `spring-boot-dependencies-4.1.0.pom`), alongside
  a per-technology `spring-boot-starter-actuator-test`; add the test starter too if the tests need
  it, matching this project's per-technology test-starter convention (CLAUDE.md). Re-verify rather
  than trusting this line.
- Liveness and readiness respond independently (probes are already on by default — verify rather
  than configuring).
- `management.endpoints.web.exposure.include` is an explicit allowlist. Not `*`.
- Integration tests, run through the real filter chain (`@SpringBootTest` + MockMvc, the shape
  `SecurityConfigIntegrationTest` already uses):
  - The liveness and readiness group paths each return 200 **anonymously**, independently.
  - `GET /actuator/health` (the parent) requires authentication — it is deliberately *not* on the
    permitAll list, per ADR-0013, because it reports honestly and that honesty is for operators.
  - `GET /actuator/metrics` requires authentication, and the test's name or Javadoc says the
    mechanism is **the absence of a matcher**, not an explicit rule.
  - `GET /actuator/env` and `GET /actuator/heapdump` are **not reachable anonymously** — assert the
    actual status returned (401 from the entry point, or 404 if they are simply not exposed) and
    say which mechanism is doing the work. Asserting "not 200" for two different reasons in one
    test hides which lever is protecting you.
  - An anonymous readiness response shows per-indicator status (`show-components=always`) and
    **no** detail payloads (`show-details=when-authorized`) — assert both halves, since this is
    the disclosure boundary ADR-0012 draws.
  - A guard that fails if the exposure list ever becomes `*` or the matcher ever becomes a blanket
    `/actuator/**`, if one can be written that genuinely observes that failure. **LESSONS: a guard
    only counts if it can observe the failure it claims to catch — prove it by breaking the thing
    and watching the guard fire.** If no honest guard is available, say so rather than shipping a
    test that reads as coverage.
- The existing `SecurityConfigIntegrationTest#unmappedApiPathIsDeniedRatherThanServed` and
  `OpenApiDocumentationTest`'s runtime anonymous-401 walk still pass.
- Full `./mvnw test` green.

## ADR — ALREADY WRITTEN
**ADR-0012** (`docs/adr/0012-actuator-exposure-is-an-allowlist-on-the-shared-chain.md`) was written
by the grilling session and records every decision above, including why a management port was
rejected and why nothing can scrape the metrics. **Read it before starting; do not write another

answer is to reopen the management-port decision.

## Relevant conventions
- **ADR-0004** — the auth boundary is response-identity-dependence, not HTTP verb; deny-by-default.
  This is the binding constraint. Note that a health endpoint returns the same answer to every
  caller, which is exactly ADR-0004's test for publicness — so health being public is *consistent*
  with 0004, not an exception to it. Say that explicitly wherever it is recorded.
- **ADR-0009** — error codes are a closed enum. Actuator writes its own response bodies and does
  not go through `GlobalExceptionHandler`; a 401 from the entry point *does* use `ErrorResponse`.
  Note which shape each denial actually returns rather than assuming.
- CLAUDE.md: constructor injection, no `@Autowired` fields; `record` DTOs; controllers never touch
  repositories.
