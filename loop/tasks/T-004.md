# T-004 — ErrorCode enum catalogue and HOLD_EXPIRED semantics
Milestone: M7 (#12)   Status: pending

## Description
**Read `docs/adr/0009-error-codes-are-a-closed-enum-and-split-on-client-action.md` first.** It
is the decision record for this entire task; this packet is its implementation.

Replace scattered error-code string literals with a closed `ErrorCode` enum carrying each
code's HTTP status and a human-readable description, and remove `ApiException`'s raw-string
constructors so there is no bypass.

### The catalogue is 21 codes, not 19
`grep -rn 'ApiException(HttpStatus' src/main/java` finds 16 service-thrown codes.
`GlobalExceptionHandler` owns 3 more (`VALIDATION_ERROR`, `INVALID_PARAMETER`,
`INTERNAL_SERVER_ERROR`). **Two more are easy to miss**: `SecurityConfig` builds
`UNAUTHENTICATED` (401) and `ACCESS_DENIED` (403) inline in `authenticationEntryPoint()` and
`accessDeniedHandler()`, because security-layer failures never reach `GlobalExceptionHandler`.
Both join the enum and `SecurityConfig` sources them from it. `ACCESS_DENIED` is unreachable
today (no rule uses `hasRole`/`hasAuthority`) and stays anyway — note that in its description
rather than deleting it.

### The `HOLD_EXPIRED` split is state-driven, not throw-site-driven
This is the subtle part and the easiest thing to get wrong. `HOLD_EXPIRED` must be returned
wherever a hold is expired **by either route**:
- stored status is already `EXPIRED` (the sweep, or a manual release per ADR-0007), **or**
- status is still `ACTIVE` but `expiresAt` is in the past (lazy expiry, ADR-0002).

Keying it on which check fired would return two different codes for one user-visible situation
depending on whether `HoldSweepService` happened to have run — observable nondeterminism that
ADR-0002 exists to hide.

**Line numbers below are current as of commit e51d37b (post-T-007) — re-derive with
`grep -rn 'ApiException(HttpStatus' src/main/java` before trusting them.** T-007 reordered
locking in both services and added a fifth `HOLD_NOT_ACTIVE` site, so any earlier description of
this task is stale.

| Site | Situation | Becomes |
| --- | --- | --- |
| `BookingService:119` | hold's stored status is not `ACTIVE` (`createFromHold`) | `HOLD_EXPIRED` if expired by either route; `HOLD_NOT_ACTIVE` if `CONVERTED` |
| `BookingService:128` | defensive zero-seat branch | unchanged — stays `HOLD_NOT_ACTIVE` |
| `BookingService:143` | **new in T-007** — per-seat ownership guard: seat's `currentHold` is null or points at a different hold | see below |
| `BookingService:154` | seat's effective status is not `HELD` — the lazy-expiry path | `HOLD_EXPIRED` |
| `HoldService:247` | `releaseHold` on a non-`ACTIVE` hold | same split as `BookingService:119` |

**On `BookingService:143`, the T-007 guard — think before assigning it a code.** It fires when a
seat under lock no longer belongs to the hold being booked. Per ADR-0009's test ("does the
client's next action differ?"), ask what the caller should do. If the seat left the hold, the
hold has in practice lost its claim, and the caller's action is the same as for any expiry:
start over. `HOLD_EXPIRED` is therefore the likely right answer — but its own comment calls the
situation "impossible" outside an ADR-0010 violation, which argues for treating it as defensive
like `:128`. Decide deliberately, record the reasoning in a comment, and do not simply
pattern-match it to whichever neighbour is closest.

**`SEAT_ALREADY_HELD` stays merged** across `HoldService:84` (Redis contention) and
`HoldService:129` (Postgres `HELD`). Identical client action, and the merge is what makes
T-003's Redis-down proof meaningful. Do not split it.

### A Hold-level expiry helper is needed
`EventSeatAvailability.effectiveStatus` operates on `EventSeat` and cannot answer "is this Hold
expired?". Add a small static sibling following that class's documented precedent (pure
function, deliberately not a Spring bean). `HoldService:134`'s lazy-reconciliation check is
related logic — consider whether it should route through the same helper rather than
duplicating the expiry comparison.

### No separate drift test
With a closed enum and no raw-string constructor, the compiler enforces structurally what a
drift test would assert. Do not add one.

## Acceptance criteria
- `ErrorCode` enum is the only place a code string or its status is defined; all 21 codes present.
- `ApiException` exposes only `(ErrorCode, String message)` and
  `(ErrorCode, String message, Throwable cause)`. Both raw-string constructors are **gone**.
- `SecurityConfig`'s two handlers build their `ErrorResponse` from the enum.
- `ErrorResponse.code` on the wire stays a plain `String` — this is an internal refactor and the
  JSON contract does not change shape.
- **Every existing `$.code` assertion still passes unchanged, except the `HOLD_EXPIRED` split.**
  Only a handful of tests should need editing — `createBookingFromLazilyExpiredHoldIsRejected` in
  `BookingIntegrationTest` (which hits the lazy-expiry site) and the corresponding cases in
  `BookingServiceTest`/`HoldServiceTest`, depending on which state each fixture puts its hold in.
  Find them with `grep -rn 'HOLD_NOT_ACTIVE' src/test`. If many more than that need editing,
  something has gone wrong — most likely you keyed the split on the throw site rather than on
  domain state. Stop and re-read ADR-0009 rather than mass-editing assertions.
- **T-007's concurrency tests assert on `HOLD_NOT_ACTIVE` too** (`HoldLockOrderDeadlockIntegrationTest`,
  `HoldReleaseSeatLockRaceIntegrationTest`, `BookingConfirmLoadIntegrationTest`). Check whether
  the states they construct are expired or `CONVERTED`, and update only where the domain state
  genuinely warrants it. Do not weaken a concurrency assertion to make it pass — if one of those
  starts failing in a way you can't explain from the split, that is a signal, not a nuisance.
- Full `./mvnw test` green, including T-001–T-003's new suites.

## Relevant conventions
- **ADR-0009** — the governing record; re-read it if any ambiguity comes up.
- ADR-0002 (lazy expiry is authoritative) — the reason the split is state-driven.
- ADR-0007 (manual hold release reuses EXPIRED status) — why a released hold is also expired.
- ADR-0008 (404 not 403 on ownership mismatch) — a *different* rule about withholding
  information from non-owners. ADR-0009's "split when the client's action differs" test does not
  reopen it; `BOOKING_NOT_FOUND` and `HOLD_NOT_FOUND` keep collapsing not-found with not-owned.
- CLAUDE.md error handling: services throw `ApiException`; `GlobalExceptionHandler` translates;
  controllers never build ad hoc error bodies. Preserve that flow exactly.
- CLAUDE.md: "Read existing files before introducing new abstractions" — read all 21 call sites
  before writing the enum.
- `CONTEXT.md`'s **Expired Hold** entry is the domain definition this task implements.
